# Contributing

Open an issue with a minimal synthetic archive recipe, observed report, expected rule and consumer/extractor context. Do not upload private releases or actual credentials. Check existing issues/PRs before starting. Keep each PR focused and preserve stable rule IDs and schema semantics.

For a behavior change, demonstrate a failing regression before the fix. Generate test fixtures locally; tests must not use network access or extract untrusted members. Run the commands in README and update docs when policy changes. AI-assisted contributions are accepted when disclosed and verified; the author remains responsible for explanations and review follow-up. Avoid bulk speculative changes.
